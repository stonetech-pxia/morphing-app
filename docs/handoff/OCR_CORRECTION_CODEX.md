## 0. 一句话

文字识别（OCR）本身有上限：图片处理再好，识别器还是会把形近的字认错（「目」→「自」、「策」→「带」、`rn` → `m`）。
要你**测试**：能不能在手机上用本机的小模型，按上下文语义把这些错字改回来，**同时不把对的改错**，而且速度、内存、下载大小在手机上可以接受。
语言：**简体中文、英文、法文、西班牙文**。

这一轮只做评测和报告，**不要往 App 里接正式功能**。结论和建议交给创始人决定，再写 DECISIONS。

### 第 2 步：纠错方法（在 Mac 上先比质量，快）

按风险从低到高，至少试前三种：

| 方法            | 做法                                                                                                                                                                                                                                                                                                                               | 风险                        |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| A. 备选重排     | 用小语言模型给 Vision 的前 N 个备选打分（困惑度），挑最通顺的。只能在识别器给的备选里选                                                                                                                                                                                                                                            | 最低，不会编出新字          |
| B. 低置信字替换 | 只动置信度低的字，只在「形近字表」（中文形近字、拉丁字母的 rn/m、l/1/I、0/O 等）里选，用语言模型判断                                                                                                                                                                                                                               | 低                          |
| C. 系统自带模型 | iOS：Foundation Models 框架（iOS 26，本机约 3B，不用下载；只在支持 Apple Intelligence 的机型和语言上可用，用 `supportsLocale` 判断）。Android：ML Kit GenAI 的 Proofreading API（Gemini Nano，跑在 AICore 上；只在部分机型上有，用 `checkFeatureStatus()` 判断；支持的语言看 `ProofreaderOptions.Language`，**有没有中文要核实**） | 中：是生成式改写，要加护栏  |
| D. 自带小模型   | 例如 Qwen2.5 0.5B / 1.5B、Gemma 3 1B / 270M、Llama 3.2 1B，量化到 4 bit。运行库：`llama.rn`（llama.cpp，GGUF，支持语法约束输出）或 `react-native-executorch`（ExecuTorch，`.pte`，要求 RN 0.81+、iOS 17、Android API 33）                                                                                                          | 中高：要下载几百 MB，要护栏 |

C 和 D 的护栏（必须有，没有护栏的结果不算）：

- **数字、金额、日期、邮箱、网址、电话一律不许改**（改了就整行退回原文）。
- 每行的改动不超过 N 个字（编辑距离上限），超过就退回。
- 输出必须和原文逐行对齐，不许增删行、不许「总结」「润色」。
- 原始识别结果一直保留，纠正后的文字能一键恢复（D-190 的精神：改动可撤销）。

## 5. 评分方法（沿用这次的写法，方便和第 3 节对比）

- 只算汉字、字母、数字（标点、空格、全角半角差异都不算），另外单独报一个「含标点」的数。
- 每一行标准答案在整页识别结果里找编辑距离最小的一段（半全局对齐：标准答案的那一行要完整对上，识别结果里起点、终点随便），累计编辑距离 ÷ 总字数 = 字符错误率。这样表格的阅读顺序不同也不影响。
- 纠错前后各算一次，再数三个数：**改对**（错 → 对）、**改坏**（对 → 错）、**没改的错**。改坏比改对更要紧。
- 英法西还要报词错误率（WER）。法文、西班牙文注意重音（é、ñ）：重音错了算错。

参考实现（Python，没有依赖）：

```python
import re, unicodedata

def norm(s):
    s = unicodedata.normalize('NFKC', s)
    return re.sub(r'[^0-9A-Za-zÀ-ɏ一-鿿]', '', s)

def semiglobal(p, t):
    # p 要完整对上，t 的起止位置随便
    prev = [0] * (len(t) + 1)
    for i in range(1, len(p) + 1):
        cur = [i] + [0] * len(t)
        for j in range(1, len(t) + 1):
            cur[j] = min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (p[i - 1] != t[j - 1]))
        prev = cur
    return min(prev)

def cer(truth_lines, ocr_text):
    text = norm(ocr_text)
    segs = [norm(l) for l in truth_lines if norm(l)]
    return sum(semiglobal(s, text) for s in segs) / sum(len(s) for s in segs)
```

（注意 `norm` 比这次会话里用的多保留了 `À-ɏ`，法文、西班牙文的重音字母才不会被删掉。）

## 6. 规则提醒

- 识别出的文字**只在本机处理**：不许发给服务器、不许发给云端模型（D-036）。在 Mac 上做质量评测时只用评测集，不用任何用户数据。
- 纠错不是「替用户写东西」（D-113），只能改识别错的字；任何会改写意思的输出都按失败算。
- 引入的模型和运行库要过 `npm run check:licenses`。模型许可证要单独核对：仓库是 AGPL，模型要能作为扩展包分发（Qwen 多数尺寸是 Apache-2.0；Gemma、Llama 有自己的使用条款，要逐条看）。
- 不 push、不部署，除非创始人明确要求；不碰生产服务 `dev.stonetech.morph-api`；自己起的服务避开 8787、8788。
- Hermes 没有 `Intl.PluralRules` 等；原生改动两边都编译（AGENTS.md）。
