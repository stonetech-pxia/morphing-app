# Tinkrum

**跟手机说几句话，做出自己的工具。** Tinkrum 是一个实验性的 App，让每个人（不只是程序员）在手机上和 AI 对话，当场搭出自己需要的日常工具：一个把票据扫进预算表的扫描按钮，一个照自己的习惯来的打卡本，一个把视频压到发得出去的按钮。

[English](README.md)

## 理念

很多人为了一个小功能，只能去下载一个满是广告的小 App，或者碰上要付费的，又不想为它掏钱。现在很多人会用 AI 给自己做工具，可大多数人不会；再说，在手机上把一个工具做出来、再让它跑起来，本来就很麻烦。

Tinkrum 想走一条不一样的路：你和 AI 对话，AI 去改一份 JSON 配置，把 App 里已经内置的工具组合起来，做成你想要的工具。App 是一个固定的内核加这份配置：内核会画页面、会跑文件工具、会存记录；页面、按钮、列表、表单、底栏、颜色，以及每个按钮背后的快捷操作，都写在配置里。做工具有两种办法：

- **跟 Tink 说**。Tink 是 App 里的助手：「加一个记我读过的书的页面，带评分」「加一个扫描成 Word 的按钮」「卡片做得平一点」。
- **从预设开始**：导入别人做好的 App 文件（Wallet、Habits、Trip……），再接着改。你也可以把自己的 App 存成预设。

Tink 只改配置，所以它做出来的东西都由内核本来就会跑的部件组成：离线能用，每次修改都能撤销，Tink 做什么都碰不到你的数据。

它当然满足不了所有需求，现在能做的事情也还不多。但我希望它能帮上上面说的这些人。

**三个承诺：**

1. **永远没有广告。**
2. **App 本身免费。** Tink 背后的模型要花钱，我的财力有限：前期我提供免费的模型额度；如果用的人多到我负担不起，会推出付费。
3. **手机上的文件和记录永远不上传。**

## Tink 只碰配置，碰不到你的记录和文件

```
     Tink 能改的                              Tink 永远碰不到的
┌─────────────────────────────┐        ┌─────────────────────────────────┐
│ App 配置（JSON）            │        │ 你的记录                        │
│   外观、底栏、App           │        │ 你的文件、照片、录音            │
│   页面和页面里的块          │        │ 从文件里识别出的文字            │
│   表和字段                  │        │                                 │
│   快捷操作、提醒            │        │                                 │
└─────────────────────────────┘        └─────────────────────────────────┘
```

- **分开存放。** 配置的各个版本、记录和文件存在不同的地方。恢复 App 的旧版本，不会动到记录和文件。
- **Tink 只能交回修改配置的操作。** 一共 14 种，没有一种能读写记录或文件。删掉一张表，表里的记录还在。
- **模型看到的是布局，不是你的内容。** 它收到的是配置和你说的那句话，从来没有记录、文件内容、文件名和识别出的文字。它也不能替你选照片或文件，图片位和文件位只能由你自己放。
- **每次修改都先检查，都能撤销。** 内核在保存之前校验每一次修改。外观的修改先进草稿，你决定应用还是离开；新功能直接生效，随时能在「改动记录」里撤销。

配置里有你自己写的文字，比如页面标题、按钮名字，这部分会发给模型。

## 怎么搭起来的

固定内核会画 26 种块，会运行 97 个动作，会存你的记录。其余都是配置，配置由三种部件组成：

- **数据**是存下来的东西：表和字段。配置里只有结构，记录本身存在手机的数据库里。
- **容器**是你看到的东西：由块组成的页面（列表、图表、日历、按钮……）。容器读数据、显示数据，从不保存、也不写数据。
- **工具**是会写的东西：块上的一键记录工具（加一条记录、打勾、+1、拖到另一列）、快捷操作（一串动作，比如 扫描 → 拉正 → PDF → 保存）和提醒。

```
                ┌───────────────────┐
       读       │       数据        │        写
   ┌───────────►│     表、字段      │◄────────────┐
   │            └───────────────────┘             │
┌──┴──────────────┐                    ┌──────────┴──────┐
│      容器       │    点一下就启动    │      工具       │
│    页面、块     ├───────────────────►│ 一键记录工具、  │
│                 │                    │ 快捷操作、      │
│                 │                    │ 提醒            │
└─────────────────┘                    └─────────────────┘
```

**例子：Habits 预设。** 每个习惯一个圆环，点一下就打卡。

```
数据      习惯          名字 · 每天几次 · 什么时段 · 哪几天
          打卡          习惯 · 日期 · 完成或跳过
          「今天」      习惯表的一个字段：今天打了几次卡，显示时现算，从不保存

容器      页面「习惯」
            宫格        每个习惯一个圆环，按 今天 ÷ 每天几次 填满
            数字        连续打卡的天数，从打卡表算
            日历        哪些天打过卡

工具      圆环上        点一下 → 给这个习惯加一条打卡
          提醒          习惯要做的那几天晚上 8 点，还没做才提醒；点「完成」加一条打卡
```

Tink 也这样搭：让它做一个打卡本，它会加表、加一页块、加块上的工具，全都是配置。三种部件之间的规则是固定的：容器只读、只导航；工具只改所在容器显示的数据，或者顺着引用找到的那一条；每份数据只存一次，别处都只引用它。

细节见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 能做什么

把一张表、一个页面和几个动作搭在一起，就能做出这样的工具：

| 例子             | 数据                                                     | 容器                       | 工具                                                                               |
| ---------------- | -------------------------------------------------------- | -------------------------- | ---------------------------------------------------------------------------------- |
| 票据记进预算     | 支出（金额、日期、商家、分类、票据）；预算（已花、还剩） | 每个分类还剩多少、支出图表 | 扫描按钮：扫描 → 拉正 → 新支出表单，合计、日期、商家给出候选值                     |
| 名片变联系人     | 联系人（姓名、公司、电话、邮箱、名片）                   | 联系人列表、每人一页       | 扫描 → 新联系人表单，给出候选值；每个联系人页上有打电话、发邮件、存成 vCard 的按钮 |
| 账单             | 账单（金额、多久一次）                                   | 到期日历                   | 账单到期那天早上 9 点提醒                                                          |
| 旅行             | 行程、预订（带票据 PDF）、行李清单                       | 按天排的行程、行李清单     | 预订前一晚提醒；装好了就打勾；行程导出成 PDF 分享                                  |
| 冲刺看板         | 任务（状态、负责人、优先级、截止日期）                   | 每个状态一列的看板         | 拖动卡片改状态；导出 Excel；工作日的站会提醒                                       |
| 视频太大发不出去 | 无                                                       | 首页上的一个按钮           | 选视频 → 压到 20 MB → 分享                                                         |

部件：

- **26 种块**：列表、清单、能拖动的看板、日历、图表、数字、表单、文件架、按钮、图片等等。
- **19 种字段**：金额、日期、评分、文件、表之间的引用、汇总、公式、日程等等；筛选、搜索、提醒，导出 CSV 和 Excel。
- **97 个在手机上运行的动作**：扫描成 PDF、Word 或 Excel，文字识别，PDF 工具，图片工具（证件照、抠图、水印），视频（压到指定大小、剪一段、转 GIF），音频（录音、语音转文字、MP3、降噪），翻译，二维码，ZIP。
- **想要什么样子都行**：颜色、字体、卡片样式、背景、图标、底栏。一个 App 里还能分出几个 App，各有各的风格。
- **文件从哪里来都行**：把照片、视频或 PDF 分享给 Tinkrum，它会推荐合适的快捷操作。
- **什么都能撤销**，一直退到第一个版本。支持中文、英文和法语。

## 不能做什么

大多数限制来自两类规则：让你的数据留在手机上，让修改 App 永远安全。下面是每条规则排除掉的事。

**文件和记录从不发给云端模型，所以：**

- Tink 读不到你存的东西：不能帮你总结合同，也不能回答关于某个 PDF 的问题。
- 读文件都在手机上做（文字识别，以及一个可选的小模型，给表单提候选值），没有大的云端模型准：候选值要自己核对；翻译用来看懂，不能当正式译文。

**所有功能离线运行，不会把你的数据发到任何地方，所以：**

- 没有联网的实时数据：没有汇率（不同货币的金额从不相加），没有天气、价格、新闻。
- 不连接别的服务：不和你的日历、银行、网盘或别的 App 同步，也不替你发邮件、发帖。分享要你亲手点，经手机的分享面板发出。
- 没有账号和同步：你的 App 和记录都在一台手机上，也没法和别人一起编辑一张表。要备份就导出。

**没有代码，只有固定清单里的部件，所以：**

- 新的块、字段或动作靠一句话做不出来，自定义界面和游戏也不行。Tink 会直说，「把这个需求告诉我们」会把这一句话发给我们。
- 快捷操作是直链：没有「如果……否则……」，没有循环，一个快捷操作也不能启动另一个。公式只有四则运算和简单的 if。

**不点就什么都不会发生，所以：**

- 没有自动化：做不到「每周一导出支出、发邮件」，也做不到新照片一来就自动归档。提醒只弹通知。（唯一的例外：回收站里放了 30 天的记录会被删除。）
- 原件永远不移动、不删除，所以 Tinkrum 没法帮你整理相册；它只处理副本。

**Tink 改的是 App，不替你办事，所以：**

- 它不回答问题，不写要发出去的消息，也不运行快捷操作。让它「把这份合同翻译成英文」，你得到的是一个在手机上运行的翻译按钮。
- 它改不了设置、改动记录、Tink 页和权限，所以你随时都能回来、撤销。

## 自己构建

需要 Node.js 22.12+ 或 24；iOS 模拟器要 Xcode，Android 要 JDK 17 和 Android SDK。

```bash
npm install
```

```bash
npm run ios
```

或者

```bash
npm run android
```

在设置 → Tink 里填上自己的 API key 之前，Tink 用离线的内置规则（[docs/API_KEY_SETUP.md](docs/API_KEY_SETUP.md)）。`npm run check` 跑 lint、类型检查和测试。自己搭转发服务器见 [docs/DEPLOY.md](docs/DEPLOY.md)。给编码代理的规则，包括上面那张清单背后的 19 条底线，见 [AGENTS.md](AGENTS.md)。
