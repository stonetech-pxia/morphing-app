# 交接：规则 + 版式记忆 + 小模型「从候选里选」，降低预填的错误率

写给 Codex。2026-10-28，创始人在 Claude Code 会话里要求写成文档并提交，交给 Codex 验证。请用中文汇报。

先读 `AGENTS.md`（必须遵守）、本目录的 `../PREFILL_REPORT.md`（现状和成绩）、`docs/DECISIONS.md` 的 D-244 和 D-273。

## 1. 要回答的问题

「记一笔」的预填（金额、日期，以及税额、单号）现在由规则加版式记忆来做。实测的情况是：

- **只靠规则**：盲测 120 条，填出来的金额里约 7% 是错的，日期约 10%。错在意思上的区分，比如不含税合计和价税合计、小费算不算进实付、英国日期日在前；还有词表里没有的说法，比如「本期应缴」。
- **规则加记忆（现在的做法）**：宁可空着。在独立的 pairs2 上，金额填错 2 个，但空着 30 个。空着集中在多了一行优惠（11）、双栏（7）、改版或分店（6），都是要「懂意思」才能补的地方。
- **只靠小模型**：交接文档的实测里，0.6B 和 0.8B 在本该空着的字段上 82/82 全部乱填；4B 乱填 2.18%，而且放不进手机。

想验证的是：**让小模型只在代码列出的候选里选一个编号，并把代码从用户第一次保存里总结出的经验写进提示词，最后由代码把关**。这样能不能在不增加填错的前提下，把空着的大部分捞回来？

## 2. 建议的做法（要验证的方案）

### 2.1 代码先列候选（已有）

`packages/core/src/prefill/candidates.ts` 的 `ruleCandidates(text, locale)` 列出文字里所有像金额、日期的地方，每个都有统一后的值、原文、行号、行内位置。系统识别用 `systemCandidates` 和 `mergeCandidates` 补充（桌面上没有系统识别，可以不用）。

候选编上号，交给模型时每个带上**它所在的那一整行**，以及前后各一行，模型需要看到标签。

### 2.2 代码把经验写成短提示（新写，不放旧值）

经验从 `learnLayout` 学到的 `LayoutMemory` 里来（`memory.ts`），由代码按固定模板生成，每个字段最多 3 条。不放上次的金额和日期，也不放上次单据的全文。例子：

- `amount`：「这家的实付上次在标签「本期应缴」后面，在页面下方约 85% 的位置。」
- `amount`：「上次同一个数还出现在「本期电费」后面，用户选的不是那个。」（从同值多处、用户选了哪一处得出）
- `date`：「这家的日期是日在前（DD/MM/YYYY）。」（从第一次能确定的日期学，例如 20/02/2026）
- `date`：「上次的日期在标签「出账日期」后面；「缴费截止日期」不是要的日期。」
- 没有记忆的新用户：不给经验，只给通用说明。

经验里出现的标签文字来自用户自己的单据，只在本机用，不发给云端 AI（D-036、D-244）。

### 2.3 模型只回答编号或「都不是」

- 系统提示词（英文写，三种语言的单据通用；下面是草稿，可以改，但要按版本记下来）：

```
You pick values from a scanned document for a form. You never write values yourself.
For each field, answer with the id of ONE candidate from the list, or "none".
Answer "none" when no candidate is clearly the requested value.
amount = the final amount paid or due, after discounts, including tax.
  Not a subtotal, not a pre-tax total, not cash given, not change, not a discount.
date = the date the document was issued or the purchase happened.
  Not a due date, delivery date, stamp date or print time.
Hints from earlier documents of this same layout (may be empty):
{hints}
```

- 用户消息：候选表，例如 `c3 | line 14 | "本期应缴：  ¥138.44" | value 138.44`。必要时加上整段 OCR 文字，这一点要分别测有和没有。
- 输出用 JSON Schema 限制成 `{"amount": "c1" | … | "none", "date": "c4" | … | "none"}`，枚举里只有这次的候选编号。这样模型**编不出**文字里没有的值，也抄不了上次的值。
- 温度 0。只要编号，不要解释。

### 2.4 代码最后把关

模型选出的候选，满足下面任意一条才填进表单：

1. 和规则（`pickAmount` / `pickDate`）或版式记忆（`readWithLayout`）选的是同一个值；
2. 金额能过加减核对：页面上「小计 − 优惠 + 税 = 这个数」或「商品加起来 = 小计」对得上（这一条要新写，误差 0.01）。

都不满足时不填，把模型选的和规则、记忆选的（去重后最多 3 个）做成**可点的候选选项**交给用户。界面还没做，评测里先按「给了候选」统计。

## 4. 评测怎么做

### 4.1 样本

- **pairs3（新做，最终成绩只看它）**：请一个没读过 `packages/core/src/prefill/`、`text-rules.ts` 和以前任何样本的人（或子代理）另写。
  - 规格照 `prefill/pairs2/` 的说明：30 个版式，中英法各 10 个，每个 4 张；第 1 张是用户保存的，第 2–4 张各一种情况：普通、拍歪、模糊、双栏、印章、多一行优惠、改版、别的分店、拍不全。
  - 再加两种：
    - 「说法变了」：同一家店，标签换了说法；
    - 「同值多处」：实付同时出现在合计行和刷卡行。
  - 真值里看不清、没拍到的写 null。
- **开发用（可以看、可以调）**：`data/` 的 477 例、`prefill/blind/`、`prefill/pairs/`、`prefill/pairs2/`。这几批 Claude Code 都看过错误了，**不能用来报最终成绩**。
- 只喂识别文字，不喂文件名、真值或 id。

### 4.2 比较的几种做法（同一批样本，每张都按「先预填、再按真值保存、记忆跟着学」的顺序）

| 代号     | 做法                                                  |
| -------- | ----------------------------------------------------- |
| R        | 只用规则（`prefillRecord` 不给 memories）             |
| RM       | 规则加记忆（现在的做法，`prefillRecord` 给 memories） |
| S0       | 模型从候选里选，不给经验提示，不把关                  |
| S1       | 模型从候选里选，给经验提示，不把关                    |
| S1G      | S1 加 2.4 的把关；不过关的算「给了候选」              |
| S1G-full | 同 S1G，但提示里加上整段 OCR 文字                     |
| E1G      | 可选：Embedding 比较候选和提示，加把关                |

`evaluate_pairs.ts` 已经有 R 和 RM 的循环，可以照着加；模型部分用 Python 也行，参考 `classification/evaluate_embedding_gguf.py` 管理 llama-server，自己起、自己停，端口避开 8787 和 8788。

### 4.3 统计什么（金额和日期分开，按语言、按情况分开）

- **填错**：填了，但不是真值。**最要紧**。
- **不该填却填了**：真值是 null，却填了。
- **填对**；**空着**。
- **给了候选、正确答案在里面**（只对 S1G 和 S1G-full）：用户点一下就对。
- **给了候选、正确答案不在里面**。
- 每张的模型耗时（桌面 CPU，p50 / p95）、峰值内存、提示词的 token 数。
- 抄旧值的次数：模型选的值等于上一张的真值、而不等于这一张的真值。

### 4.4 合格线（建议，最后由创始人定）

- S1G 的**填错加不该填却填**，占填出的不超过 2%（原来编造率的门槛），并且不多于 RM。
- 「填对」加「给了候选且正确答案在里面」，明显多于 RM 的「填对」。
- 低配候选模型在桌面 CPU 上单张不超过 1 秒，只作参考；手机上要另测。

达不到就如实写「模型帮不上忙」，不要改了样本再报。

## 5. 不要做的事

- 不接 App 界面，不改 `apps/`，不推送、不部署（AGENTS.md）。结果放 `side-session-notes`；脚本和新样本可以提交到你自己的分支，提交前问创始人。
- 不让模型直接输出值，不让模型写提示词或规则。经验提示只由代码按模板生成。
- 不把上次单据的全文、金额、日期放进提示词。
- 不在 pairs3 上看了错误再改提示词或规则又报成绩。要调，就再做一批 pairs4。
- 不用真实的个人单据。
